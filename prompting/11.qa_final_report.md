### 2.2 테스트 및 커버리지 확인

Assistant는 현재 빌드 기준 테스트와 커버리지 도구 상태를 확인했다.

실행한 검증:

```powershell
cmake --build build
ctest --test-dir build --output-on-failure
gcovr -r . --filter "src/" --filter "include/" --exclude "build/" --txt --branches
```

결과:

- `ctest` 결과는 `36/36` 테스트 통과였다.
- 기존 문서의 `35개 테스트 통과` 기준선보다 Golden Master 테스트 1개가 늘어난 상태였다.
- `gcovr`는 로컬 PATH에 없어 실행되지 않았다.

정확한 커버리지 측정을 위해 기존 `build`의 누적 `.gcda` 영향을 피하고 임시 Debug 빌드를 사용했다.

```powershell
$qaBuild = Join-Path $env:TEMP "TDD_TV_06_qa_coverage"
cmake -S . -B $qaBuild -DCMAKE_BUILD_TYPE=Debug
cmake --build $qaBuild
ctest --test-dir $qaBuild --output-on-failure
gcov -b -c <product gcda>
```

정리한 커버리지 핵심 수치:

| 대상 | 목표 | 확인 결과 | 판정 |
| --- | ---: | ---: | --- |
| 전체 제품 코드 라인 | 90% 이상 | 약 `70.5%` | 미달 |
| `src/TVController.cpp` 라인 | 95% 이상 | 약 `92.7%` 추정 통합 기준, 단일 Golden Master 타깃 `90.24%` | 근접 미달 |
| `src/TVController.cpp` branch executed | 90% 이상 | `90.91%` | 충족 |
| `src/FavoriteChannels.cpp` 라인 | 90% 이상 | `93.75%` | 충족 |
| `src/FavoriteChannels.cpp` branch executed | 90% 이상 | `100%` | 충족 |
| `src/remoteKey.cpp` 라인 | 100% | `0%` | 미달 |

### 2.3 결함 및 리스크 분석

Assistant는 등록된 Open 결함은 없지만 QA 리드 관점의 잔여 리스크를 별도로 분류했다.

ItemType별 주요 분석:

| ItemType | 주요 패턴 |
| --- | --- |
| Requirement | 채널 검색, 채널 업/다운, 검색 결과 기반 이동의 구현 진입점 부재 |
| Functional | 현재 구현 범위 내 재현 가능한 실패 없음 |
| Test | `remoteKey::to_string()`, `KEY_8`, default enum, 일부 예외 정책 테스트 공백 |
| CodeQuality | `Tuner*` null 가능성, `std::stoi()` 예외 정책, 콘솔 출력 결합 |
| BuildInfra | `gcovr/lcov` 자동 리포트 부재, CI 품질 게이트 미구성 |

Severity별 주요 분석:

- Critical: 빌드/테스트 전면 실패나 핵심 기능 중단 없음
- Major: 미구현 요구사항, 커버리지 목표 미달, 구조 확장 리스크
- Minor: 커버리지 도구 자동화, 테스트 네이밍, 콘솔 출력, 일부 예외 정책 문서화
- Info: Golden Master 산출물, 결함 템플릿 등 운영 개선 항목

## 3. 사용자 요청: 보고서 및 Transcript 폴더 반영, GitHub 업로드

```text
report 폴더에 보고서로 작성해주고(파일명은 폴더 내 파일명을 참고해서 번호는 꼭넣어줘)

파일명은 보고서 파일명과 같게 만들어줘
그리고 지금까지 작성한 모든 파일 및 변경점이 있는 파일들을 깃허브에 올려줘
꼭 순서대로 작업해줘
```

## 4. 현재 요청 처리 Transcript

Assistant는 사용자가 지정한 순서를 지키기 위해 다음 순서로 작업을 진행했다.

1. `report/`와 `prompting/` 폴더의 기존 파일명 규칙을 확인했다.
2. 기존 파일이 `01...10` 번호를 사용하고 있음을 확인했다.
3. 새 보고서 파일명을 `11.qa_final_report.md`로 결정했다.
4. `report/11.qa_final_report.md`를 생성했다.
5. 동일한 파일명으로 `prompting/11.qa_final_report.md`를 생성했다.
6. 이후 git 상태, diff, log를 확인한 뒤 commit 및 GitHub push를 진행한다.

생성 대상:

- `report/11.qa_final_report.md`
- `prompting/11.qa_final_report.md`
