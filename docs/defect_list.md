# Defect List

## 1. 문서 목적

현재까지 확인된 테스트 실패와 제품 결함을 추적한다. 각 항목은 재현 조건, 기대/실제 결과, 영향도, 원인 위치, 수정 방안, 검증 결과를 기준으로 관리한다.

## 2. 현재 결함 요약

| ID | 상태 | 심각도 | 영역 | 요약 | 관련 테스트 |
| --- | --- | --- | --- | --- | --- |
| 없음 | Closed | Info | 전체 | 현재 재현 가능한 테스트 실패 또는 Open 결함 없음 | 전체 35개 테스트 |

## 3. 최신 검증 결과

- 검증 일자: 2026-05-19
- 검증 명령:
  - `cmake --build build`
  - `ctest --test-dir build --output-on-failure`
- 결과: 35개 테스트 모두 통과
- 실패 테스트: 없음

## 4. 확인 범위

검증 대상은 `src`, `include`, `test` 아래의 현재 구현과 테스트이다.

- `TunerFakeTest`: 채널 검색, 범위 검증, 현재 채널 조회
- `TVControllerChannelChangeTest`: 숫자 입력, `KEY_OK`, `KEY_MENU`, 선행 0 정규화, 경계 채널
- `FavoriteChannelTest`: 즐겨찾기 추가/삭제/정렬, 다음 즐겨찾기 이동, 순환, 빈 목록 no-op

## 5. 결함 등록 양식

새로운 실패가 발견되면 아래 형식으로 항목을 추가한다.

### DEFECT-XXX: 결함 제목

- 상태: Open / Fixed / Closed
- 심각도: Critical / Major / Minor / Info
- 발견 테스트: `테스트_스위트.테스트_이름`
- 대상 파일: `파일명:줄번호`
- 재현 절차:
  1. 입력 또는 사전 조건을 작성한다.
  2. 실행 명령을 작성한다.
  3. 관찰된 실패를 작성한다.
- 기대 결과: 기대한 동작을 작성한다.
- 실제 결과: 실제 실패 로그 또는 관찰 결과를 작성한다.
- 원인 분석: 결함 원인을 작성한다.
- 최소 수정 방안: C++17 기준의 최소 변경 방향을 작성한다.
- 검증 결과: 수정 후 빌드 및 테스트 결과를 작성한다.
