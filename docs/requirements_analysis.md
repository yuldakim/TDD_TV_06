# TDD_TV 요구사항 분석

## 1. 동작별 비즈니스 규칙

| 동작 | 입력 | 현재 구현 상태 | 비즈니스 규칙 | 구현 관점 확인 포인트 |
| --- | --- | --- | --- | --- |
| 한 자리 채널 변경 | 숫자 1개 + `KEY_OK` | 구현됨 | 숫자 키를 임시 버퍼에 저장하고 `KEY_OK` 입력 시 해당 채널로 변경한다. 예: `1`, `OK` -> `1` | `processingCH`가 비어 있지 않을 때만 `Tuner::setCH()`를 호출해야 한다. |
| 두 자리 채널 변경 | 숫자 2개 | 구현됨 | 숫자 키 2개가 입력되면 `KEY_OK` 없이 즉시 채널을 변경한다. 예: `1`, `2` -> `12` | 버퍼 길이가 2가 되는 순간 자동 확정 후 버퍼를 비워야 한다. |
| 연속 숫자 입력 | 숫자 4개 이상 | 구현됨 | 숫자 2개 단위로 채널 변경을 반복한다. 예: `1`, `2`, `3`, `4` -> `12` 변경 후 `34` 변경 | 자동 확정 후 다음 숫자는 새 버퍼의 첫 자리로 처리되어야 한다. |
| 앞자리 0 처리 | `0`, 숫자 | 구현됨 | 두 자리 입력이 완성되면 정수 변환 후 문자열로 되돌려 앞자리 0을 제거한다. 예: `0`, `7` -> `7` | `std::stoi("07")` 결과를 `std::to_string()`으로 변환해 `"7"`로 전달한다. |
| 미완성 숫자 취소 | 숫자 1개 + `KEY_MENU` | 구현됨 | 아직 확정되지 않은 숫자 입력은 `KEY_MENU`로 취소된다. | 취소 후 `KEY_OK`를 눌러도 이전 숫자로 채널 변경하면 안 된다. |
| 빈 버퍼 확인 | `KEY_OK` | 구현됨 | 입력 중인 숫자가 없으면 아무 동작도 하지 않는다. | `processingCH.empty()` 조건으로 `setCH()` 호출을 막아야 한다. |
| 선호 채널 추가 | `KEY_FAV` | 구현됨 | 현재 채널이 선호 목록에 없으면 추가한다. | `Tuner::getCurrentCH()` 반환값을 정수로 변환해 저장한다. |
| 선호 채널 삭제 | `KEY_FAV` | 구현됨 | 현재 채널이 이미 선호 목록에 있으면 목록에서 삭제한다. | `std::find()`로 동일 정수 채널을 찾아 제거한다. |
| 선호 목록 정렬 | 여러 채널에서 `KEY_FAV` | 구현됨 | 선호 채널 목록은 오름차순으로 유지한다. | 추가 후 `std::sort()`를 호출하며 중복은 토글 삭제 정책으로 방지한다. |
| 다음 선호 채널 이동 | `KEY_NEXT_FAV` | 구현됨 | 현재 채널보다 큰 선호 채널 중 가장 작은 채널로 이동한다. | 정렬된 목록에서 `std::upper_bound()`를 사용한다. |
| 다음 선호 채널 순환 | 마지막 선호 채널에서 `KEY_NEXT_FAV` | 구현됨 | 현재 채널보다 큰 선호 채널이 없으면 가장 작은 선호 채널로 이동한다. | `upper_bound()`가 `end()`이면 `favorites[0]`으로 이동한다. |
| 선호 목록 없음 | `KEY_NEXT_FAV` | 구현됨 | 선호 채널이 없으면 채널을 변경하지 않는다. | `favorites.empty()`이면 즉시 종료한다. |
| 채널 검색 | 채널검색 키 | 미구현 | 모든 시청 가능 채널을 검색해 저장해야 한다. | 현재 `remoteKey`에 채널검색 키가 없고 `TVController` 분기도 없다. |
| 채널 업/다운, 검색 결과 없음 | 채널 업/다운 키 | 미구현 | 검색 결과가 없으면 현재 채널 기준으로 +1/-1 이동하며 0~99에서 순환한다. | 현재 `remoteKey`에 업/다운 키가 없고 순환 로직도 제품 코드에 없다. |
| 채널 업/다운, 검색 결과 있음 | 채널 업/다운 키 | 미구현 | 저장된 검색 결과 안에서 다음/이전 채널로 이동한다. | 검색 결과 컨테이너와 현재 채널 기준 탐색 정책이 필요하다. |

## 2. 문자열 비교/분기 시 주의점

1. `remoteKey` 분기는 문자열 비교보다 `enum class` 기반 `switch`를 우선한다.
   - 숫자 키인지 판별할 때 `"0"`~`"9"` 문자열을 비교하지 말고 `remoteKey::KEY_0`~`KEY_9` case에 명시적으로 포함시키는 방식이 안전하다.

2. `to_string(remoteKey)` 결과는 채널 숫자 누적에 사용된다.
   - 숫자 키는 `"0"`~`"9"`를 반환해야 한다.
   - 비숫자 키는 `"OK"`, `"MENU"`, `"FAV"`, `"NEXT_FAV"`를 반환하지만 현재 제품 코드에서는 주로 숫자 키 case 안에서만 누적에 사용된다.

3. 채널 문자열 비교에는 `find()`보다 `==` 또는 정수 변환 후 비교를 사용한다.
   - 예를 들어 `"1"`과 `"10"`을 비교할 때 `find("1")`를 사용하면 `"10"`도 매칭되어 오동작할 수 있다.
   - 현재 선호 채널은 `std::stoi()`로 정수 변환 후 `std::find(favorites.begin(), favorites.end(), curr)`로 정확히 비교한다.

4. 앞자리 0이 있는 채널은 문자열 그대로 비교하지 않는다.
   - `"07"`과 `"7"`은 문자열로는 다르지만 같은 채널 번호로 봐야 한다.
   - 현재 두 자리 자동 확정 경로는 `std::stoi()` 후 `std::to_string()`을 적용해 `"07"`을 `"7"`로 정규화한다.

5. `std::string::find()`의 반환값은 반드시 `std::string::npos`와 비교해야 한다.
   - `find()` 결과를 단순 boolean처럼 사용하면 위치 `0`이 `false`처럼 취급되는 버그가 생길 수 있다.
   - 이 프로젝트의 현재 채널/선호 채널 판별에는 부분 문자열 검색이 필요하지 않으므로 `find()` 사용을 피하는 것이 좋다.

6. `Tuner::getCurrentCH()` 반환값은 숫자 문자열이라는 전제가 있다.
   - `KEY_FAV`, `KEY_NEXT_FAV`는 `std::stoi(tuner->getCurrentCH())`를 호출한다.
   - 빈 문자열, 공백, 비숫자 문자열이 들어오면 예외가 발생할 수 있으므로 테스트 더블도 실제 계약에 맞는 숫자 문자열을 반환해야 한다.

## 3. 예외/경계값 조건

1. 채널 범위는 `0`~`99`이다.
   - `0`, `99`는 유효한 경계값이다.
   - `-1`, `100`, `"9999"` 등은 튜너 계층에서 거부되어야 한다.

2. `TVController`는 현재 구현 기준으로 채널 범위를 직접 검증하지 않는다.
   - 숫자 입력 UI는 최대 두 자리까지만 자동 확정하므로 일반 경로에서는 `0`~`99` 안에 들어온다.
   - 최종 유효성은 `Tuner::setCH()` 계약에 의존한다.

3. `std::stoi()` 예외 가능성이 있다.
   - `std::invalid_argument`: 빈 문자열 또는 비숫자 문자열 변환 시 발생 가능.
   - `std::out_of_range`: 정수 범위를 초과하는 문자열 변환 시 발생 가능.
   - 현재 구현은 예외를 잡지 않으므로 테스트 더블과 실제 튜너는 숫자 문자열 계약을 지켜야 한다.

4. `KEY_OK`는 빈 입력에서 무시되어야 한다.
   - 빈 `processingCH`에서 `Tuner::setCH("")`가 호출되면 `std::stoi()` 기반 튜너 구현에서 예외가 날 수 있다.

5. `KEY_MENU`는 미확정 입력만 취소한다.
   - 이미 두 자리 입력으로 자동 확정된 채널은 취소하지 않는다.
   - 예: `4`, `5`, `6`, `MENU`, `OK`는 `45`만 확정되고 `6`은 무효화된다.

6. 선호 채널 목록이 비어 있을 때 `KEY_NEXT_FAV`는 no-op이어야 한다.
   - 빈 벡터에서 `favorites[0]` 접근이 발생하면 안 된다.

7. 선호 채널이 1개뿐일 때 `KEY_NEXT_FAV`는 같은 채널로 이동할 수 있다.
   - 현재 채널과 같은 값만 선호 목록에 있으면 `upper_bound()`가 `end()`를 반환하고 첫 선호 채널로 순환한다.

8. 선호 채널 저장 시 중복이 없어야 한다.
   - 같은 채널에서 `KEY_FAV`를 다시 누르면 추가가 아니라 삭제되어야 한다.

9. 원시 포인터 `Tuner*` 수명은 호출자 책임이다.
   - `TVController` 생성 시 `nullptr`이 전달되면 현재 구현은 보호하지 않으며, 키 처리 중 역참조로 실패할 수 있다.

10. 미구현 요구사항의 경계값은 별도 설계가 필요하다.
    - 채널 업: `99 -> 0`
    - 채널 다운: `0 -> 99`
    - 검색 결과 기반 업/다운: 현재 채널이 검색 목록에 없을 때 다음/이전 후보 선택
    - 채널 검색 결과가 비어 있을 때의 업/다운 정책
