# Golden Master 회귀 테스트 구현 보고서

## 1. 보고서 개요

본 보고서는 `TVController`의 현재 동작을 출력 기반 Golden Master로 고정하기 위해 C++17, Google Test, CMake/CTest 기반 회귀 테스트를 설계하고 구현한 결과를 정리한다.

요청 범위는 다음 네 가지였다.

- expected 출력 파일 생성 및 보관 전략
- Google Test에서 파일 비교 테스트 구현
- CMake/CTest 통합
- CI 자동 실행 구성

## 2. 변경 대상

이번 작업에서 추가하거나 수정한 주요 파일은 다음과 같다.

- `test/TVControllerGoldenMasterTest.cpp`
- `test/golden/TVControllerGoldenMaster.approved.txt`
- `CMakeLists.txt`
- `.github/workflows/ci.yml`
- `docs/golden_master_test.md`

제품 코드인 `src/TVController.cpp`, `src/remoteKey.cpp`, `include/TVController.h`, `include/Tuner.h`, `include/remoteKey.h`는 변경하지 않았다.

## 3. Golden Master 기준 파일 전략

기준 출력 파일은 `test/golden/TVControllerGoldenMaster.approved.txt`에 보관하도록 했다. 이 파일은 현재 정상 동작으로 승인한 텍스트 출력이며, Git에 포함되어 회귀 기준으로 관리된다.

테스트 실행 중 실제 출력은 빌드 디렉터리 아래 `test-output/TVControllerGoldenMaster.received.txt`에 생성된다. 기준 파일과 실제 출력이 다르면 테스트를 실패시키고, 실패 메시지에 approved/received 경로를 표시한다.

기준 파일 갱신은 자동으로 수행하지 않는다. 의도된 동작 변경을 리뷰한 뒤에만 `UPDATE_GOLDEN_MASTER=1` 환경 변수를 사용하는 `update_golden_master` CMake 타깃으로 갱신할 수 있게 했다.

## 4. Google Test 구현 내용

`TVControllerGoldenMasterTextTestFixture`를 새로 추가해 여러 사용자 시나리오를 하나의 안정적인 텍스트 출력으로 렌더링한다.

포함한 대표 시나리오는 다음과 같다.

- 한 자리 채널 입력 후 `KEY_OK` 확정
- 네 자리 연속 입력 시 두 자리 단위 자동 확정
- 앞자리 `0` 정규화
- `KEY_MENU`로 미확정 입력 취소
- 즐겨찾기 추가/삭제/정렬
- 다음 즐겨찾기 이동
- 마지막 즐겨찾기에서 첫 즐겨찾기로 순환
- 즐겨찾기가 비어 있을 때 no-op

테스트는 `std::cout` 출력을 캡처해 현재 구현의 콘솔 출력까지 Golden Master에 포함한다. Windows와 Linux CI 간 줄바꿈 차이 때문에 비교 단계에서는 CRLF/LF를 정규화한다.

## 5. CMake/CTest 통합

`CMakeLists.txt`에 `TVControllerGoldenMasterTest` 실행 파일 타깃을 추가하고, `gtest_discover_tests()`로 CTest에 등록했다.

컴파일 정의로 다음 경로를 테스트 코드에 주입했다.

- `GOLDEN_MASTER_APPROVED_FILE`: 소스 트리의 승인 파일
- `GOLDEN_MASTER_RECEIVED_FILE`: 빌드 트리의 실제 출력 파일

또한 기준 출력 갱신 전용 타깃을 추가했다.

```powershell
cmake --build build --target update_golden_master
```

## 6. CI 구성

`.github/workflows/ci.yml`을 추가해 GitHub Actions에서 다음 순서로 자동 검증한다.

1. Checkout
2. CMake configure
3. CMake build
4. `ctest --output-on-failure`

CI에서는 `UPDATE_GOLDEN_MASTER`를 설정하지 않으므로, Golden Master 출력이 변경되면 기준 파일을 자동 갱신하지 않고 실패로 보고한다.

## 7. 실행 및 검증 결과

로컬 검증 명령은 다음과 같다.

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

Golden Master 단독 검증 명령은 다음과 같다.

```powershell
ctest --test-dir build -R TVControllerGoldenMaster --output-on-failure
```

최종 검증 결과 전체 테스트가 통과했다.

```text
100% tests passed, 0 tests failed out of 36
```

## 8. 참고 사항

IDE linter는 CMake include 경로와 Google Test FetchContent 결과를 인식하지 못해 `TVController.h` 또는 `gtest/gtest.h` 관련 진단을 표시할 수 있다. 실제 CMake 빌드와 CTest 실행은 정상 통과했다.

기존 `build/` 디렉터리는 테스트 실행으로 생성/변경되는 산출물이 많으므로, 소스 변경과 분리해 관리하는 것이 좋다.
