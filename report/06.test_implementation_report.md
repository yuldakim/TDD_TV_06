# TEST_F 기반 테스트 구현 보고서

## 1. 보고서 개요

본 보고서는 `TVController`, `Tuner` 협력 동작에 대해 C++17, Google Test 기반 단위 테스트를 보강한 결과를 정리한다. 요청 범위는 동작별 최소 5개 `TEST_F`, `EXPECT_EQ`/`ASSERT_EQ` 중심 검증, 경계값 포함, Given-When-Then 주석 구조 적용이었다.

## 2. 변경 대상

- `test/TVControllerTest.cpp`
- `test/FavoriteChannelTest.cpp`
- `test/TunerTest.cpp`

제품 코드(`src/`, `include/`)는 변경하지 않고, 현재 구현 계약을 기준으로 테스트만 정리했다.

## 3. 구현한 테스트 범위

### 채널 검색 및 변경

`TunerFakeTest`에서 `seekCH()` 동작을 5개 이상 검증했다.

- 초기 채널 `0`에서 검색 시 `5`로 변경
- 반복 검색 시 `5 -> 10 -> 15` 순서 변경
- 상한 경계 `99` 이후 wrap-around로 `4` 반환
- 반복 검색 결과가 항상 `0`~`99` 범위 유지
- 명시적으로 설정한 현재 채널 기준으로 검색 진행

### 지정 채널 변경

`TVControllerChannelChangeTest`에서 숫자 키 입력을 통한 지정 채널 변경을 검증했다.

- 한 자리 입력 후 `KEY_OK`로 확정
- 두 자리 입력 즉시 자동 확정
- 자동 확정 후 추가 `KEY_OK`가 no-op인지 검증
- 연속 4자리 입력이 두 자리 단위로 확정되는지 검증
- `KEY_MENU`가 미확정 입력만 취소하는지 검증
- `0`, `99`, 앞자리 `0` 정규화 등 경계값 포함

### 현재 채널 조회

`TunerFakeTest`에서 `getCurrentCH()` 계약을 5개 이상 검증했다.

- 초기 채널 `0` 조회
- 하한 경계 `0` 설정 후 조회
- 상한 경계 `99` 설정 후 조회
- 여러 유효 채널 설정 후 마지막 값 조회
- 유효하지 않은 설정 실패 후 기존 채널 유지

### 선호채널 등록 및 삭제

`FavoriteChannelTest`에서 선호채널 목록의 상태 변화를 검증했다.

- 현재 채널을 선호 목록에 추가
- 동일 채널 재입력 시 삭제
- 중복 없이 토글 처리
- 역순 입력 후 오름차순 정렬 유지
- 경계 채널 `0`, `99` 등록
- 중간 선호채널 삭제 후 나머지 정렬 유지

### 선호 채널간 이동

`FavoriteChannelTest`에서 `KEY_NEXT_FAV` 이동 정책을 검증했다.

- 현재 채널보다 큰 다음 선호채널로 이동
- 선호채널이 1개일 때 같은 채널 유지
- 마지막 선호채널에서 첫 선호채널로 순환
- 선호 목록이 비어 있으면 no-op
- 현재 채널이 전체 선호채널보다 낮으면 첫 선호채널로 이동
- 현재 채널이 목록 사이 값이면 바로 위 선호채널로 이동

## 4. 테스트 구조 개선

기존 approval 파일 비교 중심 테스트를 명시적 assertion 중심 테스트로 정리했다. 테스트 더블은 검증 목적에 맞춰 단순화했다.

- `RecordingTunerForController`: 설정 이력과 현재 채널을 기록해 `TVController` 숫자 입력 결과를 직접 검증
- `FakeTunerForFav`: 현재 채널과 선호채널 목록 변화를 검증
- `FakeTunerForTunerTest`: `seekCH()`, `setCH()`, `getCurrentCH()` 계약을 독립적으로 검증

모든 신규/수정 테스트는 Given-When-Then 주석 구조를 사용했다.

## 5. 경계값 반영

다음 경계 및 특이 조건을 테스트에 포함했다.

- 채널 하한 `0`
- 채널 상한 `99`
- 앞자리 `0` 입력 정규화: `07 -> 7`
- 자동 확정 이후 `KEY_OK` no-op
- `KEY_MENU`에 의한 미확정 입력 취소
- 빈 선호채널 목록에서 이동 no-op
- 선호채널 wrap-around
- 유효하지 않은 채널 설정 실패 후 현재 채널 유지

## 6. 검증 결과

다음 명령으로 빌드 및 테스트를 확인했다.

```powershell
cmd /c "cmake --build build && ctest --test-dir build --output-on-failure"
```

결과는 전체 35개 테스트 통과였다.

```text
100% tests passed, 0 tests failed out of 35
```

PowerShell 환경에서는 `&&` 문법이 지원되지 않아 동일한 체인 명령을 `cmd /c`로 실행했다.

## 7. 참고 사항

현재 `docs/requirements_analysis.md`, `docs/test_plan.md`에는 채널 검색 키, 채널 업/다운 키가 미구현 요구사항으로 정리되어 있다. 따라서 제품 코드에 없는 리모컨 키나 외부 API를 새로 만들지 않고, 현재 존재하는 `Tuner::seekCH()`, 숫자 입력, 선호채널 동작 범위 안에서 테스트를 작성했다.
