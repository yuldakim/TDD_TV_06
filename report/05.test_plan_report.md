# TVController 테스트 계획 보고서

## 1. 보고서 개요

본 보고서는 `TVController`의 단위 테스트 전략을 정의한다. 대상 프로젝트는 C++17, Google Test/Google Mock, CMake 기반이며, 가능한 경우 `gcov/lcov` 또는 `gcovr`를 활용해 커버리지를 측정한다.

테스트 계획의 핵심 목표는 채널 입력, 입력 취소, 즐겨찾기 등록/삭제/순환 동작을 요구사항 기준으로 검증하고, 미구현 요구사항은 보류 테스트 항목으로 분리해 추적 가능하게 만드는 것이다.

## 2. 테스트 대상

- `include/TVController.h`
- `src/TVController.cpp`
- 협력 객체: `Tuner`
- 보조 타입: `remoteKey`, `to_string(remoteKey)`

## 3. TEST_F 기반 테스트 전략

컨트롤러 테스트는 공통 fixture를 기준으로 재구성하는 것을 권장한다. 현재 즐겨찾기 테스트는 `TEST_F` 기반이나, 숫자 입력 테스트는 `TEST` 기반이므로 fixture를 도입해 mock/fake 튜너 준비와 입력 helper를 공통화한다.

권장 fixture는 다음과 같다.

- `TVControllerDigitInputTest`: 숫자 입력, `KEY_OK`, `KEY_MENU`, 두 자리 자동 확정 검증
- `FavoriteChannelTest`: 즐겨찾기 추가, 삭제, 정렬, 다음 즐겨찾기 이동 검증
- `TVControllerExceptionalTest`: 비정상 `Tuner` 응답, `nullptr` 정책 등 특이 케이스 검증
- `RemoteKeyTest`: `remoteKey` 문자열 변환 계약 검증
- `TunerContractTest`: 채널 범위 `0`~`99` 계약 검증

### P2: 미구현 요구사항 보류 테스트

현재 구현에는 채널 검색, 채널 업/다운 키가 없으므로 다음 항목은 보류 테스트로 관리한다.

- 채널 검색 키 입력 시 시청 가능 채널 목록 저장
- 검색 결과 없음 상태에서 채널 업 `99 -> 0`
- 검색 결과 없음 상태에서 채널 다운 `0 -> 99`
- 검색 결과 `[4, 6, 14]`에서 현재 `6`일 때 업 `14`, 다운 `4`
- 검색 결과 `[4, 6, 14]`에서 현재 `15`일 때 업 `4`, 다운 `14`

## 6. 예외 및 특이 케이스

| 분류 | 조건 | 현재 기대 결과 |
| --- | --- | --- |
| 비숫자 현재 채널 | `getCurrentCH()`가 `"ABC"` 반환 후 `KEY_FAV` | `std::invalid_argument` 전파 |
| 빈 현재 채널 | `getCurrentCH()`가 `""` 반환 후 `KEY_NEXT_FAV` | 즐겨찾기 상태에 따라 예외 전파 가능 |
| 정수 범위 초과 문자열 | 매우 큰 숫자 문자열 반환 | `std::out_of_range` 전파 가능 |
| `nullptr` 튜너 | `TVController(nullptr)` 후 키 입력 | 역참조 실패 가능 |
| `Tuner::setCH()` 예외 | 튜너가 범위/형식 예외 발생 | 예외 전파 |
| 알 수 없는 enum 값 | `static_cast<remoteKey>(999)` | 현재 명시적 처리 없음 |

`nullptr` 튜너와 알 수 없는 enum 값은 제품 정책 확정 후 테스트를 고정해야 한다. 현재 구현 기준으로는 방어 코드가 없으므로 death test 또는 생성자 예외 정책 중 하나를 선택하는 것이 필요하다.

## 8. gcov/lcov 측정 및 개선 전략

현재 `CMakeLists.txt`는 `Debug` 빌드에서 `--coverage -O0` 옵션을 추가한다. GCC 또는 MinGW 계열 컴파일러에서는 다음 절차로 측정한다.

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
cmake --build build
ctest --test-dir build --output-on-failure
```

`lcov` 사용 시 제품 코드 중심 리포트는 다음과 같이 생성한다.

```powershell
lcov --capture --directory build --output-file build/coverage.info
lcov --remove build/coverage.info "*/_deps/*" "*/test/*" "*/build/*" --output-file build/coverage.filtered.info
genhtml build/coverage.filtered.info --output-directory build/coverage-html
```

Windows에서 `lcov` 사용이 어렵다면 WSL, MSYS2, Linux CI 또는 `gcovr`를 사용한다.

```powershell
gcovr -r . --filter "src/" --filter "include/" --exclude "build/" --html --html-details -o build/coverage.html
gcovr -r . --filter "src/" --filter "include/" --exclude "build/" --txt
```

측정 후에는 라인 커버리지보다 브랜치 커버리지 공백을 우선 확인한다. 특히 `KEY_NEXT_FAV`의 빈 목록, 다음 원소 존재, wrap-around 경로가 모두 통과되는지 확인해야 한다.
